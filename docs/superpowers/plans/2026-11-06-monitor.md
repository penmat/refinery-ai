# Refinery Monitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `refinery monitor`, a local, read-only workflow dashboard with live and historical graph views.

**Architecture:** Existing workers persist lifecycle journals independently of the dashboard. A local Python server reads those journals and serves snapshots, SSE updates, and compiled React assets. A shared frontend reducer drives React Flow and summary/detail panels.

**Tech Stack:** Python 3.12, FastAPI/Uvicorn, React, TypeScript, Vite, React Flow, Dagre, Vitest. Compile frontend assets into the Python package; no Node runtime for installed users.

**Spec:** `docs/superpowers/specs/2026-11-06-monitor-design.md`

## Global Constraints

- Serve on loopback only; same-origin assets and APIs; validate Host and Origin.
- Read-only monitoring; attaching, detaching, and server failures cannot affect workers.
- Reuse `.refinery/migration-events/<run_id>.jsonl`; no competing migration writer.
- Preserve compatibility with v1 migration journals and existing recovery behavior.
- Current repository by default; explicit repository, port, and no-browser options.
- New runs persist topology; older runs label current topology as a fallback.
- No raw prompts, source, secrets or model responses in events.
- Missing tokens/pricing display unavailable, never zero; initial usage coverage may remain unknown.
- No SQLite index, automatic history deletion, remote hosting or workflow controls.
- Do not overwrite unrelated changes or disturb ongoing migration work.

## Review Focus

- A journal grows between snapshot and subscription: replay after snapshot cursor loses no event (Task 3).
- Resuming a profile repeats graph nodes: identity and generation preserve visits and child links (Task 1).
- State paths or journals are symlinks: requests cannot escape the configured state root (Task 2).
- A worker dies without a final event: UI reports unknown liveness, never inferred success/failure (Task 4).
- Installed wheel omits web assets: isolated installation still serves the dashboard without Node (Task 5).

## File Structure

- `src/refinery_ai/monitor/models.py`: normalized API models and topology metadata.
- `src/refinery_ai/monitor/recording.py`: profile journaling and invocation correlation context.
- `src/refinery_ai/monitor/topology.py`: safe graph topology serialization/persistence.
- `src/refinery_ai/monitor/journals.py`: validated incremental readers and run discovery.
- `src/refinery_ai/monitor/server.py`: local API, SSE and packaged asset serving.
- `src/refinery_ai/monitor/cli.py`: startup, browser launch and shutdown.
- `src/refinery_ai/monitor/static/`: compiled, versioned frontend output.
- `web/monitor/`: frontend sources, reducer, graph, panels and tests.
- Existing workflow/event files receive narrow instrumentation additions.
- `tests/test_monitor_recording.py`, `tests/test_monitor_journals.py`, `tests/test_monitor_server.py`, `tests/test_monitor_cli.py`: behavioral verification.

### Task 1: Persist parent execution identity and graph metadata

**Files:** Create monitor package, `models.py`, `recording.py`, `topology.py`; modify `workflows/profile.py`, `workflows/migration.py`, `migrations/events.py`; add `tests/test_monitor_recording.py`.

**Interfaces:**
- `InvocationContext`: parent run ID and parent execution ID carried by a ContextVar across synchronous child invocation.
- `ProfileReporter`: `emit(phase, lifecycle, execution_id, *, outcome=None, duration_seconds=None, child_run_id=None)` writes versioned events; `close()` closes its journal.
- `GraphTopology`: graph kind, schema version, topology version/hash, node IDs/labels and directed edges.
- `save_topology(state_root: Path, run_id: str, topology: GraphTopology) -> None` writes an atomic sidecar under `monitor-topologies/`.
- Migration events accept optional parent identity fields with defaults, retaining old v1 readability.

- [ ] Write tests proving legacy migration records still validate; child migration events inherit the exact profile node invocation identity; standalone runs have no parent.
- [ ] Write tests for repeated profile cycles and checkpoint resume: unique execution IDs, stable run identity across an interrupted invocation, resumed generation and no replayed completed effects. Legacy profile checkpoints lacking monitor identity receive a new monitoring segment without changing recovery semantics.
- [ ] Write tests that snapshot topology matches actual compiled graph nodes/edges and extracting it never invokes worker effects.
- [ ] Run `uv run pytest tests/test_monitor_recording.py --no-cov`; confirm new behavior fails before implementation.
- [ ] Implement correlation and profile lifecycle wrappers around existing graph nodes. Persist profile identity in checkpoint state with backward-compatible optional fields; emit explicit run terminal status. Reuse migration journal writer and add optional fields only.
- [ ] Serialize topology from the real compiled graph at invocation setup. Write before initial events; exclude model configuration and runtime service objects.
- [ ] Run recording tests plus existing profile, migration-event and workflow characterization tests; confirm passed assertions preserve recovery behavior.

### Task 2: Read historical and growing journals safely

**Files:** Create `monitor/journals.py`; add `tests/test_monitor_journals.py`.

**Interfaces:**
- `JournalCatalog(repository: Path, state_directory: Path)` confines discovery to migration/profile event directories.
- `list_runs() -> list[RunSummary]`, `snapshot(run_id: str) -> RunSnapshot`.
- `JournalTail.read_batch(limit: int = 256) -> list[MonitorEvent]` tracks byte offset and sequence; buffers at most a 1 MiB event line.
- `RunSnapshot`: run summary, normalized events, topology, cursor and diagnostics. Unsupported/malformed events become diagnostics rather than invented execution data.

- [ ] Write tests for partial UTF-8/trailing lines, subsequent appends, bad complete records, duplicate/out-of-order sequences, unsupported schema, empty journals and missing metadata.
- [ ] Write tests rejecting invalid run IDs, traversal and symlinked files/directories. Enforce a 1 MiB line limit and reject truncation/replacement explicitly so stale offsets do not silently skip events.
- [ ] Run `uv run pytest tests/test_monitor_journals.py --no-cov`; verify failure.
- [ ] Implement incremental parsing, normalized migration/profile events and sidecar loading. Only complete newline-terminated records enter live snapshots; snapshots return the last included sequence. Current-topology fallback is explicit and cannot instantiate effectful workflow services.
- [ ] Implement safe discovery and per-run diagnostic isolation: one corrupt journal must not hide healthy runs. Keep state root configuration compatible with existing absolute state-directory settings.
- [ ] Run journal and recording tests; confirm bounded tail batches, historical/live equivalence and path confinement.
- [ ] Review diff and commit task files.

### Task 3: Serve snapshots and reconnectable live updates

**Files:** Create `monitor/server.py`; modify `pyproject.toml` for server dependencies; add `tests/test_monitor_server.py`.

**Interfaces:**
- `create_app(repository: Path, state_directory: Path, *, allowed_host: str) -> FastAPI`.
- `GET /api/runs` returns run summaries.
- `GET /api/runs/{run_id}` returns `RunSnapshot`.
- `GET /api/runs/{run_id}/events?after=N` returns SSE; Last-Event-ID overrides query cursor on reconnect. Each event has `id: <sequence>` and normalized JSON data.
- SSE sends bounded replay batches, periodic comment heartbeats, and terminal diagnostic/reset messages for journal corruption/replacement.

- [ ] Write tests for run discovery, missing/invalid IDs, denied foreign Origin/Host and static asset confinement.
- [ ] Write tests that append an event after snapshot but before subscription, then assert every sequence arrives once after cursor. Reconnect with Last-Event-ID and assert no skipped event.
- [ ] Write tests for client disconnect, idle stream, corrupt journal and bounded batch processing. Assert stream cleanup never writes to journals or controls workers.
- [ ] Run `uv run pytest tests/test_monitor_server.py --no-cov`; verify failure.
- [ ] Implement API and asynchronous SSE using incremental tails, polling every 250 ms and disconnect cancellation. File access must not block the event loop for unbounded work. No permissive CORS or arbitrary artifact reads.
- [ ] Serve packaged assets with SPA fallback only for UI routes; unknown API routes remain errors. Configure loopback Host/Origin validation from the actual bound port.
- [ ] Run server, journal and recording tests; review and commit task files.

### Task 4: Build the React Flow dashboard

**Interfaces:**
- API types mirror normalized Python schemas; `applyEvents(state, events)` is the single immutable reducer for snapshot replay and live updates.
- Graph consumes topology plus reduced node visits; details/timeline use the same state.
- EventSource subscribes after snapshot cursor, reconnects and deduplicates by run/sequence/event ID. Close previous subscription when selection changes.

- [ ] Write reducer tests comparing all-at-once replay with incremental/reconnected delivery; assert repeated visits, repair generation and failed-build outcomes remain distinct.
- [ ] Write tests for empty state, missing tokens/cost, child navigation, no double-counted parent/child usage, and late responses after selecting another run.
- [ ] Write tests ensuring an unmatched start is shown as outcome unknown/last observed, stream disconnection changes connection status only, and topology edges are not labelled traversed without evidence.
- [ ] Run frontend tests and verify failure before reducer implementation.
- [ ] Implement reducer and API client. First release displays tokens/cost as unavailable unless supported normalized usage records exist; do not read OTLP counters as historical totals or invent pricing.
- [ ] Implement run navigation, summary cards, stable Dagre graph layout, node visit details, activity timeline, migration breadcrumbs, connection status, empty/error states and responsive styling. Label fallback topology; display text/icons as well as color. Persist no secrets in browser storage.
- [ ] Run `npm test -- --run`, `npm run typecheck`, and `npm run build` in `web/monitor`; confirm all succeed.
- [ ] Open the dashboard in a browser with fixture and actual journals. Check zoom/pan, selection, migration navigation, retries, errors, loading/empty states and narrower windows. Inspect console and network failures.

**Interfaces:**

- `serve_monitor(repository: Path, state_directory: Path, port: int, open_browser: bool) -> None` binds 127.0.0.1, reports its URL, opens a browser only after readiness and shuts down cleanly on Ctrl-C.

## Self-review

The five tasks cover identity/topology persistence, safe history, live transport,
UI, CLI and distribution. Full local cost instrumentation is explicitly deferred
under the approved design's allowance for unknown usage in the first release.
Existing migration/profile execution semantics remain authoritative. Execution
must first establish an isolated workspace and recheck the active migration work
before editing shared event or workflow interfaces.
